# Web front end (beginner guide)

The site in `web/` is a thin client. It never analyses images itself. It sends the file to `POST /v1/check` and draws the JSON that comes back.

Flow: pick, drop or paste an image, or paste an https image link into the "or paste an image link" field next to the upload control and press Check (pasting plain text that is an https URL anywhere on the page fills that field). Pasting works on any tab: the page switches to the Image tab first. The link is sent as the form field `url` and the server fetches it. Then the browser checks type and size (10 MB), shows a preview and uploads with a progress bar. The result card shows the verdict band, then "X% likely AI" (`probability_ai`) as the main number with "Detector score: Y%" smaller beneath it, then the explanation and cues, a "Detector only" tag when the explainer was unavailable, a note when it overrode the detector (for example "The detector leaned AI, but Claude's visual check found it real."), a C2PA badge, the scope note and the disclaimer.

**Landing view.** The page opens on the Video tab: the headline says SixFingers checks the picture and the voice, a one-line subhead explains the two checks (frames scored by the detector and read by a visual judge, plus a voice deepfake check, then one overall verdict), and a 3-step strip reads Upload a video, We check the frames and the voice, One verdict (with which part flagged it). The page reads `audio_enabled` from `GET /v1/health` once (with retries). When it is false, the hero and strip use picture-only wording and say the voice check is off. A muted line under the upload box says the voice check is a prototype that scores only the first 4 seconds and results can be wrong. The old image hero shows on the Image tab. Tab order is Video, Image, then Audio (only when audio is on).

Two tabs sit above the upload control: **Image** (the flow above) and **Video**. The Video tab takes uploads only; links come later. Pick or drop an MP4, WebM or MOV file. The browser checks the type and the 100 MB limit, then shows a preview player and uploads with a progress bar. The video takes longer than an image because the server samples frames, so the request waits up to 5 minutes. The line under the control says a video counts as 3 checks, and the length limit is 60 seconds (the server checks it).

The video result card shows the overall verdict, then two equal boxes, **Picture** (verdict, explanation, frame thumbnails) and **Voice** (verdict and score, or "No voice found in this video." when there is no soundtrack). The Picture box shows the verdict band, Claude's explanation, and the cues with the frame number and time, for example "Frame #5 at 1.4 s, hands". A **frame strip** lists every sampled frame in time order with a small thumbnail, its time, and its score as a percentage AI-like with its band. Frames that the explanation cites are marked "Cited". The thumbnails are cut in the browser from the file you picked, so nothing extra is uploaded. The card also gives the video score (the average of the 4 most AI-like frames). When audio checks are off on the server, the Voice box shows the server's note, "Audio is not analysed yet."; when they are on, it shows the soundtrack's score (see below). If the explanation step was unavailable, the card says so and shows the detector result only.

Video errors: 400 "Could not read this video.", 413 "That video is too large or too long. The limits are 100 MB and 60 seconds.", 415 "Unsupported file type. Use MP4, WebM or MOV.", 422 "We can't analyse this video.", 429 "Too many checks. The limit is 10 per hour and a video counts as 3. Try again later.", 503 "Video checks are not available right now.". A timeout in the browser says "The check took too long. Try a shorter video.".

**Audio tab (prototype).** On load, the page asks `GET /v1/health` whether the API has audio checks on (`audio_enabled`). Only then does a third tab, **Audio**, appear, so the public site is unchanged while the API has them off. Pick or drop a WAV, MP3, FLAC, OGG, M4A or WebM file (25 MB, 60 seconds). The result card shows the band, a "Prototype" tag, the chance that the voice is AI-generated as a percentage, and a one-line limits note: only the first 4 seconds are scored, and the model was trained on read English speech. There is no written explanation, because the explainer cannot hear sound. The first audio check is slower while the server loads the speech model, so the request waits up to 2 minutes.

Errors map to HTTP status: 400 for a link ("That link can't be used.", or "Couldn't fetch that image. The link may have expired or not be public."), 504 the link timed out, 502 the link could not be fetched, 429 rate limit, 413 too big, 415 wrong type, 422 the image cannot be analysed ("We can't analyse this image."). A line under the upload control says uploading means agreeing to the Terms. `/terms` is a short acceptable-use page, linked in the footer next to Privacy. A spent daily budget arrives as `judge_unavailable_reason: "budget"` on a normal 200 response.

The upload goes direct to the API because Vercel limits request bodies to about 4.5 MB. Set `NEXT_PUBLIC_API_URL` for the target API, or `NEXT_PUBLIC_MOCK=1` to try the UI with no server. Set `NEXT_PUBLIC_TURNSTILE_SITE_KEY` to turn on the Cloudflare Turnstile bot check (`web/lib/turnstile.ts`): the page loads Cloudflare's script once, gets a fresh single-use token for every image, link and video check, and sends it in the `cf-turnstile-response` header. The widget stays hidden unless Cloudflare needs the visitor to do something. Without the key there is no script and no widget. If the server cannot confirm the token, the result shows the detector only, with the note "We couldn't confirm you're human, so only the detector result is shown." A token expires 5 minutes after it is made, so a very slow video upload (close to the 300-second upload timeout) can also end up detector-only. Details: `web/README.md`.

Keep `web/lib/types.ts` in step with `ml/common/api_models.py`.

The About page explains the two percentages in plain words.

## Result card extras

- **Provenance first.** When the image has a C2PA manifest, a banner ("Signed by <issuer>: marked AI-generated", or "Signed by <issuer>") sits above the verdict. Without one, provenance stays in its section lower down.
- **Evidence boxes.** Each cue may carry `box` = `[x0, y0, x1, y1]` as 0-1 fractions of the upright image. The card draws them over the local preview as numbered rectangles (absolutely positioned `<span>`s in percent), numbered like the cue list. Hovering or focusing a cue highlights its box, and hovering a box highlights its cue. A checkbox hides the boxes. Link checks have no local preview, so they show the cue list only.
- **Uncertain.** An `uncertain` verdict adds a note ("We would rather say we don't know than guess") with the calibrated probability. Under the big number, "What this number means" links to `/scorecard#calibration`.
- **Download report.** The button stamps the UTC time and calls `window.print()`. Print CSS (`@media print` in `globals.css`) hides everything except the result card, so the report is the card itself: verdict, probability, boxes over the preview, cues, provenance, detector score, model version and disclaimer. Choose "Save as PDF" in the print dialog. Nothing is uploaded or stored.

## Feedback card

Under each real result (not in mock mode, and not when the response has no `check_id`) a small card asks "Was this right?" with Right / Wrong / Not sure buttons. After a choice it offers "What was it really?" (AI-made / Real / Don't know), an optional comment box (500 characters, with a counter and a reminder not to type personal details) and Send, which posts to `POST /v1/feedback`. It then shows a thank-you line, or an error (result expired, already sent, too much feedback, server unreachable). The choices are ordinary buttons with `aria-pressed`, so they work with Tab, Enter and Space. The card is hidden when printing the report. A new result gets a fresh card.

## Scorecard page

`/scorecard` is rendered on the server from `GET /v1/scorecard` (see `docs/api.md`, **Scorecard**). It shows the catch rate per generator, the false-alarm rate per real-photo source (clean and compressed), clean vs compressed overall, the Claude Haiku visual check's accuracy and uncertain rate, the calibration sentence (`#calibration`), a Usage block and limits. The Usage block shows checks since launch and in the last 30 days, and "X of Y answers said the result was right" once there are at least 20 feedback answers ("Not enough feedback yet" before that), with a note that this is not a measured accuracy. If the endpoint fails or returns 404 it says the scorecard is unavailable. It is linked from the header and from the facts line on the home page. Mock mode uses `MOCK_SCORECARD` in `web/lib/api.ts`; `MOCK_RESULT` has two boxed cues and one whole-image cue.

## Style

Plain CSS in `web/app/globals.css`, the system font stack (no web font), white background in every mode (no dark theme), colours and radii copied from avikwok.dev (green `#16a34a`, darker green-ink for text and buttons, 16px cards, 6px nested items, 4px chips). Verdict colours: AI red, real green, uncertain amber, each at least 4.5:1 on white. The "How it works" strip on the main page reads the model version and one metric from `GET /v1/model` and hides them if the call fails.
